# Telegram-уведомления PULL

Откройте `setup.py` через Python на Windows. Нужны Python 3 с tkinter, Node.js 22 и установленные npm-зависимости проекта. Монитор использует тот же `lib/engine.ts`, что и сайт. Отдельная копия формулы не поддерживается.

1. Введите токен существующего бота от @BotFather в поле с маскировкой. Лучше использовать отдельного бота: webhook не удаляется, другие обработчики getUpdates могут перехватить код подключения.
2. Нажмите «Подготовить подключение», отправьте показанную команду боту в личном чате, нажмите «Подтвердить чат».
3. «Отправить тест» отправляет одно тестовое сообщение в подтверждённый чат.
4. Выберите сети, порог и размер позиции. «Сохранить и включить» запускает скрытый локальный процесс. Окно и сайт можно закрыть. «Остановить» отключает новые отправки; начатый запрос может завершиться.

По умолчанию: каждые 120 секунд, оценка от 75, TVL от $10 000, позиция $200, горизонт 1 час, два последовательных подтверждения. Первая успешная непустая выборка каждой сети запоминается без рассылки. Новый подходящий пул или пересечение порога подтверждаются двумя наблюдениями. После отправки тот же пул должен сначала опуститься ниже порога минус 10, и с прошлой отправки должно пройти 6 часов. Отсутствующие/неполные ответы прерывают подтверждение. Не более 5 сообщений за цикл. GeckoTerminal trending pools — ограниченная выборка, не все пулы сети.

Состояние хранится в `%LOCALAPPDATA%/PULL-notifier/state.sqlite`; токен зашифрован Windows DPAPI для текущего пользователя. База и токен не попадают в сайт, Git или командную строку. Не переносите базу между пользователями Windows: токен потребуется подключить заново. Журнал хранится 30 дней. Сохранённая история предотвращает повторную рассылку после перезапуска.

Монитор не запускается автоматически после перезагрузки Windows. Откройте настройки и нажмите «Сохранить и включить». Во время сна/выключения компьютера проверки не выполняются. Не запускайте отдельные копии проекта с разными моделями одновременно: один локальный lock допускает только один процесс.

При таймауте отправки невозможно узнать, доставил ли Telegram сообщение. Такой сигнал отмечается как неопределённый и автоматически не повторяется во избежание дублей; это видно в журнале. При явном HTTP 429 сигнал остаётся доступным для повтора после указанной Telegram паузы. Ошибки 400/401/403 останавливают мониторинг до исправления подключения.

Тесты без реальных отправок: `python -m unittest discover -s notifier -p test_monitor.py`. Проверка модели, шифрования Windows, защиты от дублей, первого запуска, пропусков данных и ошибок Telegram.

Документация API: https://core.telegram.org/bots/api

## Локальный источник для сайта
Запустите PowerShell-скрипт start-collector.ps1 (из папки notifier), затем на сайте нажмите «Подключить компьютер» и разрешите доступ к локальной сети. Выбор сохраняется в этом браузере. Сбор идёт примерно раз в 2–3 минуты; сайт читает готовый кэш раз в 30 секунд. Telegram использует тот же кэш. После перезагрузки запустите скрипт снова. Автозапуск Windows не устанавливается.
Сервис слушает только 127.0.0.1:18767 и принимает браузерные запросы только от вашего сайта. API-ключи не выдаются. Поиск и избранное в локальном режиме ограничены текущими кандидатами GMGN; отсутствующие пулы не получают новую оценку. При отказе источника время последнего успешного наблюдения сохраняется, устаревшие оценки отключаются.
